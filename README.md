# 運彩分析機器人（足球 + NBA → Telegram）

用約兩年的歷史賠率回測「盤口變化、各家賠率差、球員休息/傷兵」等規律，
只把**通過統計檢驗**的規律拿來即時監控，有訊號就推播到 Telegram，並自動追蹤實戰成績。

> ⚠️ 研究用途，不構成投注建議。博彩長期平均是負報酬（莊家抽水足球約 6%、NBA 約 4.4%），
> 回測有效不代表未來有效。請只用輸得起的錢。

## 資料來源（全部免費）

| 用途 | 來源 | 內容 |
|---|---|---|
| 足球歷史 | football-data.co.uk | 11 個聯賽 2024-25、2025-26、2026-27 已完賽，約 8,300 場；多家博彩公司 + Betfair 交易所的開盤/收盤賠率、亞洲讓球、大小球 |
| NBA 歷史 | ESPN | 2024-25、2025-26 例行賽 + 季後賽 2,638 場；ESPN BET / DraftKings 開盤與收盤的讓分、大小分、不讓分 |
| 即時盤口 | ESPN scoreboard | NBA + 11 個足球聯賽 + 歐冠/歐霸，DraftKings 開盤與即時盤口 |
| NBA 傷兵 | ESPN injuries | 主力（場均 ≥15 分）狀態變成 Out / Doubtful 或傷癒回歸 |
| 多家比價（選用） | The Odds API | 填 `ODDS_API_KEY` 後，每天 2 次比較各家賠率與 Pinnacle/Betfair 公平價 |

## 回測結果摘要（2026-10-14）

完整表格在 `data/backtest_report.md`。

- **NBA 不讓分盤口變動 ≥5pp → 跟進資金方向**：583 注、命中 59.5%、ROI +7.3%、p=0.045，兩季都正 → **⭐ 啟用**
  - 兩家博彩公司分別 +7.2% / +7.4%，17 個月中 11 個月賺錢；但拿掉最賺的 10 注後只剩 +0.8%，證據偏弱
- **[交叉] NBA 讓分盤移動 ≥2 分、但大小分幾乎沒動 → 跟進讓分**：309 注、贏盤 57%、ROI +9.2%、p=0.045，兩季都正 → **⭐ 啟用**
  - 比上一個穩：拿掉最賺的 10 注仍有 +6.1%，兩家博彩公司都正；大小分同時變動時就沒效（-2.6% / +0.2%）
- NBA 讓分盤移動 ≥3~4 分跟進：+3.3% ~ +6.5%，方向一致但未達顯著 → 參考
- [交叉] 足球讓球 ≥1 球但預期低進球（大2.5 <50%）→ 買受讓方 +5.2%（197 注，不顯著）；同條件買讓球方 -11.4%
- 所有「反向」（賭市場反應過度）策略都是負報酬：**盤口往哪邊移，通常是對的**
- 足球：盤口變化、亞洲讓球移動、尖銳盤 vs 平均盤都**沒有找到穩定優勢**；早盤比價（最高賠率比 Betfair 公平價高 5% 以上）+5% 但不顯著
- MLB（7,409 場、含 118 場季後賽）：盤口變化、讓分×大小交叉都**沒有**找到優勢；季後賽盲買熱門 +3.0%、盲買主隊 -6.0%（樣本小）
- 盲目下注基準：足球主勝 -8.6%、客勝 -11.2%；NBA 主隊讓分 -2.9%

## 更多資料的回測（2026-10-23）

資料往前延伸：足球 2019-20 起 **8 季 27,441 場**（football-data 從這季開始有收盤）、NBA 2016-17 起 **11 季 12,848 場**
（2023-24 之前只有收盤，盤口變化類只能用 2023-24 起的 4 季）、MLB 2019 起 **7 季 17,265 場**（2020 縮水季不用）。
腳本：`research/extended_backtest.py`（在 GitHub Actions 的 `research.yml` 跑，結果是 artifact）。

| | 原本季別 | 新增季別（樣本外） | 全部 |
|---|---|---|---|
| ⭐ NBA 讓分移動 ≥2 分但大小沒動 → 跟進 | 312 注 +9.3% | 145 注 +2.8% | 457 注 +7.3%，4/4 季為正 → **保留** |
| ⭐ NBA 不讓分勝率變動 ≥5pp → 跟進 | 590 注 +7.0% | 342 注 −5.1% | 932 注 +2.6%，2/4 季 → **降為參考** |
| 新 ⭐ 足球大小 2.5 機率變動 ≥8pp → 跟進 | 56 注 | 152 注 +7.7% | 208 注 +10.8%（p=0.02），**8/8 季為正** |
| NBA 讓分移動 ≥3 / ≥4 分跟進 | +3.2% / +6.4% | −9.6% / −22.4% | 不成立 |

- **歷史相似盤口沒有幫助**：逐季留一，加權後的 log loss 不比只看市場好；用它挑「每場最佳且 EV ≥ 2%」的選項，
  足球 9,141 注 −5.0%（8 季只有 1 季為正）、MLB 770 注 −4.0%、NBA 77 注 −19.7% → 改成只當參考
- 校準重新驗證：見上面「市場機率校準層」
- 莊家角度 8 季都一樣：讓球盤主隊比客隊多虧（−5.2% vs −2.6%）、Bet365 5 倍以上冷門平均 −17.5%、1.5 倍以下 −2.6%
- NBA 動能（上一場大勝 / 大幅打出盤口後跟買或反買）：11 季全部是負的，沒有規律
- NBA 主力缺陣、疲勞：讓分 3/3 季改善 → 保留；不讓分 2/3 季 → 拿掉

## 從莊家角度的回測（2026-10-23）

足球 11 個聯賽 8,301 場、NBA 兩季、MLB 三季，一律用季別交叉驗證（用其他季估計、在沒看過的那季測試）。

**莊家靠抽水賺錢，而且抽水不是平均分配：**
- 抽水（中位數）：足球勝平負 Bet365 6.1%、市場平均 6.0%、Betfair 交易所 0.6%；NBA 不讓分 4.4%、讓分/大小 4.8%；MLB 4.5–4.7%
- 冷門被抽最多：Bet365 對每個結果都多收約 2.3–2.9 個百分點，換算成相對值，冷門（機率 <15%）多收 25–29%、熱門（>60%）只多收 3.5%
- 依賠率全買的實際 ROI（Bet365 收盤）：1.0–1.5 倍 -2.3%、1.5–5 倍約 -6~-7%、5–10 倍 -15.4%、10 倍以上 -45.5%；NBA 5–10 倍 -15.5%；MLB 3–5 倍 -17.9%
- 和局抽最少：全買和局 -3.6%，全買主勝 -8.6%、客勝 -11.1%
- 亞洲讓球對主隊多抽：全買主隊 -6.0%、全買客隊 -3.4%（3 季都是客隊少虧）；主隊實際贏盤率比去水機率低 1.6–2.3pp
- 串關的抽水相乘：每關 5% → 二串約 10%、三串約 14%；每關 10% → 三串約 27%
- 用各家最高價買，1.5–5 倍區間只剩 -1~-2%：抽水是最大的敵人

**「反買大眾」全部失敗**（莊家沒有系統性地坑熱門球隊）：
- 足球：反買被莊家壓價的熱門隊（亞盤）-6.7%；反買上一場大勝、近 3 場全勝的隊都是負的
- NBA：反買上一場大勝 ≥15 分的隊 -12.2%；反過來跟買 +2.6%（p=0.23）、≥20 分跟買 +5.9%（p=0.08），但兩季差很多（-0.5% / +12.2%）→ 不採用
- MLB：全部負

**莊家的判斷有沒有漏洞：**
- Bet365 開盤比交易所開盤準：開盤時 Bet365 看起來比交易所划算的注，到收盤反而變差 5–8%
- 「Bet365 長期比交易所看好某隊」、Elo、近況、上場淨勝：第一次測試看似有效，但那次的比較把「重新校準」的效果也算進特徵；
  改成公平比較（校準 + 特徵 vs 只校準）後都沒有穩定改善 → 不採用

**採用**：足球讓分加「主隊截距」（5:5 的盤 → 主隊 48.2%、客隊 51.8%），3 個測試季都改善，實戰一樣有自動關閉的保護；
「最推薦」的串關會顯示每關抽水與整張累積抽水。

**⚽ 足球以大小、讓球為主**（10/25）：每場附 🎯 比分預測（兩隊預期進球、最可能的 3 個比分）與「運彩常見盤口」合理賠率表
（大小 1.5–4.5、讓 1.5 / 2.5）；推薦、最推薦與串關的足球選項只從大小、讓球挑（不讓分賠率太低）。
比分模型 = 市場勝平負 + 大小拆成兩隊預期進球的 Poisson，加 Dixon-Coles 低比分修正（純 Poisson 低估和局）
與「淨勝 ≥2 球」校準（純 Poisson 高估大比分約 3pp；8 季逐季留一 7 季改善，見 research/goals_calibration.py）。

**「實際勝率比模型高就多推」**（10/28）：research/error_momentum.py 用足球 8 季、NBA 11 季檢查——
某類型最近一直贏市場（例如這季大分一直開），接下來跟著買仍然虧（足球 8 季 0 季為正、NBA 10 季 0 季為正），
市場會很快修正。所以只對通過回測的 ⭐ 策略加碼：回測 uplift 與實戰推播結果按注數合併（learning.strategy_uplift），
實戰比回測好就自動多推，比回測差就自動少推。

**💱 運彩比價**（oddscheck.py，10/24）：直接打運彩開的賠率，例如 `湖人 1.75`、`湖人 -3.5 1.80`、`湖人 大228.5 1.75`、`利物浦 和 3.40`；
好幾行就當成一張串關。回覆估計勝率、合理賠率、期望值與「值得 / 接近公平 / 不值得」。運彩盤口跟 DK 不同時，
足球用 Poisson 比分模型換算，NBA / MLB 用以 DK 盤口為中心的常態近似。

**📊 戰績網頁**（dashboard.py + `.github/workflows/dashboard.yml`）：https://yoman951208-source.github.io/sports-betting/
最推薦單關 / 二串一 / 三串一、每日串關、推播訊號的累計損益圖與明細、模型校準表；每天 10:25、13:25、23:25 更新。
（repo 是公開的，所以這個網頁也是公開的。）

單場分析的版面（10/23 整理）：

## 執行架構

| 在哪裡 | 做什麼 |
|---|---|
| **GitHub Actions**（公開 repo，免費、不限分鐘） | `.github/workflows/betting.yml` 每小時 :07、:37 跑 `main.py cloud`：一輪監控 + 到期的每日工作（台灣時間判斷）。資料庫與策略檔存在 **`data` 分支**，歷史賠率快取用 actions/cache |
| **Cloudflare Worker**（`worker/`，免費） | Telegram webhook 接收訊息與按鈕：說明／選單秒回，其他指令立刻回「處理中」並觸發 GitHub `command.yml`，約 30–60 秒回覆。**電腦關機也能用按鈕** |
| **GitHub Actions `command.yml`** | 由 Worker 觸發，跑 `main.py command` 處理一則指令（只讀資料，不寫回） |
| 本機（工作排程器 SportsBetting） | **已停用**（10/23 起改用 webhook）。要改回本機接收：先 `deleteWebhook`，再啟用工作排程器（`main.py bot`） |

Telegram 金鑰放在 repo 的 Actions secrets（`TELEGRAM_BOT_TOKEN`、`TELEGRAM_CHAT_ID`），不在程式碼裡。
要改回全部在本機跑：工作排程器參數改成 `main.py loop`，並停用 workflow。

## 每天自動做的事（台灣時間；GitHub 排程可能延遲幾分鐘）

| 時間 | 內容 |
|---|---|
| 每 30 分鐘 | 抓盤口快照；開賽前 3 小時內記錄每個選項的模型預測；完賽自動結算預測與串關 |
| 10:00 | 🧾 盤後分析：足球賽果、🏀 **NBA 專屬檢討**（讓分/大小/不讓分表現、資金方向、兩隊得分王與缺陣者、模型預測對照）、MLB、串關結果與累計戰績、模型學習狀態與校準表 |
| 12:00 | 📅 每日賽事總覽 |
| 12:30 | 🏆 今日最推薦（單關/二串一/三串一，存檔追蹤戰績）＋ 🎟️ 每日串關（未來 24 小時，足球 + MLB + NBA；同一關最多 2 張、同一場最多 2 張），存檔供隔天結算 |
| 週一 | 📊 每週成績 + 重新下載資料並回測 |

**估計勝率怎麼來**（10/23 用更多季別重新驗證後）：校準後的市場機率 + NBA 主力狀態；⭐ 訊號成立時再加上回測的 uplift。
「歷史相似盤口」只當參考資料，不再加權進勝率（learning.py 每天只顯示實戰中兩者誰比較準）。

**市場機率校準層**（calibration.py）：去水用 power 方法（足球 8 季中 7 季比等比例準），
只保留逐季留一每一季都改善的修正：足球讓分扣回莊家對主隊多抽的部分（8 季中 7 季）、NBA 讓分加主力缺陣與疲勞（3 季都改善）。
拿掉了原本只用 2–3 季驗證、季別變多後不穩的：足球勝平負的冷熱門校準（8 季只有 4 季）、NBA 的盤口移動校準。
每場預測也記錄未校準的機率；實戰滿 200 場且校準明顯較差（t>2）會自動關閉。係數每週重新估計。

## 已知限制

- NBA 歷史只有一家博彩公司（ESPN BET → DraftKings），且不知道 ESPN「收盤」的確切擷取時間；
  即時訊號在開賽前 3 小時發出，若之後還有大變動（例如臨時傷退）就抓不到。每週報告的 CLV 會顯示這個落差。
- 足球即時盤口只有 DraftKings，回測則是多家平均；足球「開盤」定義也不同（程式會優先用賽前 1–2 天的快照對齊）。
- 足球沒有免費的傷兵資料源；球員異動主要靠盤口變化間接反映。
- 運彩本身的歷史賠率抓不到（官網擋爬蟲），所以回測用的是國外博彩公司價格。
